# Solution Overview

## What We Built

We built an integrated web platform that helps pharmaceutical and pharmacovigilance teams analyze medicine safety data and check regulatory submission readiness in one place.

The platform analyzes official FAERS/AEMS adverse-event data to identify potential drug-event associations using transparent statistical methods. It also allows users to review pharmaceutical dossier documents against verified ICH CTD requirements, identify missing or unclear sections, and generate actionable reports.

## How It Works

1. Safety data is analyzed: The system works with official FAERS/AEMS data and normalizes drug and adverse-event names for consistent analysis.
2. Potential signals are detected: The system creates a 2×2 contingency table and calculates PRR and Chi-square values for drug-event combinations.
3. Signals are classified: Based on transparent application-configured criteria, results are classified as Potential Safety Signal, Weak/Emerging Signal, or No Signal.
4. Trends are analyzed: The system analyzes reporting patterns over time and identifies meaningful trends or clusters when sufficient data is available.
5. Dossier is reviewed: Users provide pharmaceutical dossier documents for submission-readiness analysis.
6. Documents are mapped to CTD: The system identifies relevant CTD sections across Modules 1–5 and compares them with verified ICH requirements.
7. Gaps are identified: Each applicable requirement is categorized as Present, Missing, Unrecognized, or Not Applicable.
8. Readiness is calculated: Module-wise and overall completeness are calculated from the deterministic requirement-status results.

9. eports are generated: Safety analysis, submission readiness, and combined regulatory reports provide a consolidated view for expert review.

## Key Design Decisions

Decision	Rationale
Used deterministic statistical analysis for safety signals	PRR, Chi-square, contingency tables, and signal classification must be transparent, reproducible, and explainable rather than generated by AI.
Used verified ICH CTD requirements for submission readiness	Regulatory requirements should come from trusted requirements data instead of allowing an AI model to invent requirements.
Separated AI explanations from core calculations	AI can make results easier to understand while critical statistical and regulatory decisions remain deterministic.
Combined safety analysis and submission readiness	Bringing both workflows into one platform provides users with a unified view of safety findings and regulatory documentation gaps.
Used transparent signal-classification rules	Clear criteria make it easier for users and reviewers to understand why a result received a particular classification.
No database dependency for the frontend application	The application can be run locally without requiring database installation or database configuration.
